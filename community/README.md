# 共享区：大家共同维护的流程攻略

这个目录里的内容是**给所有人用的**：任何人都可以改进一份已有攻略，或者提交一份新攻略。

| 文件 | 是什么 |
|---|---|
| `guides/<id>.yaml` | 一份结构化的流程攻略，例如"申根短期旅游签"：要回答哪些问题、要做哪几步、每步要什么材料、原始资料里的原话 |
| `material_types.yaml` | 材料类型词表：把"身份证原件 + 复印件""居民身份证"这类不同叫法对齐到同一种材料，匹配个人材料库靠它 |

完整的数据结构和校验规则见 [`specs/002-guide-to-track/spec.md`](../specs/002-guide-to-track/spec.md)。

## 硬规则：这里绝对不能有个人信息

攻略写的是"这类事一般怎么办"，不是"我这次怎么办"。以下内容**永远不能**出现在这个目录里：

- 任何人的真实姓名、证件号、电话、地址、具体存款金额
- 你自己的情况（身份、婚否、做到了哪一步、用了哪份材料）——这些属于你本机材料根目录下的 `tracks/`，界面会自动写到那里
- 原始攻略的大段原文（`evidence` 只摘不超过 60 字的原话，并注明来源）

## 怎么贡献一份攻略

1. **找资料**：官网说明、小红书/知乎攻略、你自己办过的经验都可以。记下来源链接和信息时效（例如"截至 2026-05"）。
2. **交给你本地的 Agent 整理**：把资料和 [`specs/002-guide-to-track/prompt.md`](../specs/002-guide-to-track/prompt.md) 一起交给你自己的 Claude Code / Codex 等 Agent，让它按指令整理成 `guides/<id>.yaml`。本项目不内置任何模型调用，也不会把你的资料发给第三方——用谁的 Agent、花谁的额度，由你自己决定。
3. **校验**：在仓库根目录运行

   ```bash
   PYTHONPATH=src uv run python -m core.guides
   ```

   全部显示 ✓ 才算通过。✗ 下面会用中文说明哪里不对。
4. **自己检视一遍**：启动本地服务（见仓库根目录 README），打开 `/guides.html`，点进你的攻略看预览，模拟回答几个问题，确认步骤和材料符合常识。
5. **提交**：一份攻略一个提交，提交信息写清楚来源，例如 `feat(guides): add japan tourist visa (Shanghai consulate)`。

## 改词表时要注意

- 新增叫法之前先查一下是否已有对应类型，避免同一种材料出现两个 key。
- 词表加载时会自动检查：两个不同类型的叫法在规范化之后不能相同。改完一定要跑一遍上面的校验命令。
- `normalize` 规则会影响**所有**攻略的匹配，改它之前要想清楚。
