# Backlog（明确推迟的想法）

这些想法在讨论过程中被提出，都有价值，但**不在当前 MVP 范围内**。记在这里是为了不丢失，同时明确提醒任何协作的 Agent：看到这些想法时不要主动开始实现，除非项目主明确要求把某一项移进 `SPEC-mvp.md`。

- **按时间归档个人记录**（工资条等）。属于核心库范畴（机械的归档规则），但优先级低于把材料数据库+表单代填这条主线跑通。
- **从工作周报自动生成简历要点**。属于 Agent 层范畴（需要总结和写作判断），和材料/表单这条主线关系不大，适合作为独立的后续模块。**现状**：新版「办事工作台」已提供"工作笔记"页面，把周报素材和简历素材作为**本浏览器草稿**（localStorage `pa-workbench-v1`）分开记录——只是记事，不做任何生成；**自动从周报生成简历要点这一 AI 能力仍未采纳、未实现**，存储格式与是否要做 AI 生成都还没定。旧的 `web/index.html` 里那个"工作经历和简历" tab 仍是空壳占位，不要看到它存在就当作已被采纳。
- **证件照管理与规格校验**（存储、按用途分类、校验是否符合某国签证的尺寸/背景要求）。存储和分类部分属于核心库；校验部分可能只需要普通图像处理，不一定需要模型判断，留给下一轮架构讨论时评估。
- **小红书材料清单自动检索**（目前这一步项目主手动完成：自己搜索后把结论整理成结构化清单喂给系统）。属于 Agent 层范畴，自动化收益不确定，先手动跑几轮再决定是否值得做。**拆分说明（2026-09-23）**：其中"用户把找到的攻略贴进来 → AI 解析成结构化流程"这一半已被采纳，见 `specs/002-guide-to-track/spec.md`；"自动去小红书搜索/抓取攻略"这一半仍是 backlog，且 002 明确不做。
- **手机端提醒/确认联动**。例如材料快过期时提醒、在手机上确认表单字段。MVP 阶段先在桌面环境跑通闭环，移动端联动作为后续扩展。
- **GitHub 自动云同步机制的具体自动化**（例如定时自动 commit/push）。数据与代码分离的原则已经锁定（见 SPEC-mvp.md 第 3 条），但"多久同步一次、用什么机制触发"留待后续。
- **面向多用户的复用形式**——这条拆成两档，轻的那档已经在 `specs/001-visa-material-hub/` 这一轮讨论中正式采纳，不再算 backlog：
  - **（已采纳，不再是 backlog）个人自部署开源**：把这个"壳子"开源到 GitHub，让其他人各自在自己电脑上装一份、用自己的材料根目录，互不相干，每人一份独立本地实例。核心库接口参数化、不硬编码个人场景（见 SPEC-mvp.md 第 2 条），具体约束见 `.specify/memory/constitution.md`。
  - **（仍是 backlog）托管式多租户服务**：打包成一个大家共用的托管服务/开放 API，一套后端服务多个用户。这会把项目性质从"个人工具"变成"要对他人敏感数据负责的产品"，涉及认证、数据隔离、隐私合规等全新的设计维度，当前不做。
- **Track 模板 vs 实例**（2026-09-23 提出，来自对 schengen-visa-guide 的调研）：把"某类事要做什么"（模板，不含个人信息，可以分享、开源、由社区贡献）和"我这一次办这件事"（实例，挂着我的材料和进度）分开。好处是别人写好的攻略可以直接变成模板，不用每个人都重新抽取一遍。现在的 `specs/002-guide-to-track/` 只有实例，等 Phase A/B 跑通、积累几个 Track 之后再评估要不要拆。
- **PersonalProfile 字段扩展参考 visa-form-copilot**（2026-09-23）：[huaxialucaicaizi/visa-form-copilot](https://github.com/huaxialucaicaizi/visa-form-copilot) 的 `references/profile-schema.md` 给出了一份跨美签/英签/申根/澳签复用的申请人档案结构（身份、护照、联系方式、家庭、工作、教育、出行和签证历史、拒签记录等），其中"未知一律填 null，绝不当成否"的原则值得照搬。等做 MVP 第 2 项"表单代填"时再参考。注意：该仓库没有开源许可证，只借鉴思路，不复制内容。
