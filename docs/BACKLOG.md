# Backlog（明确推迟的想法）

这些想法在讨论过程中被提出，都有价值，但**不在当前 MVP 范围内**。记在这里是为了不丢失，同时明确提醒任何协作的 Agent：看到这些想法时不要主动开始实现，除非项目主明确要求把某一项移进 `SPEC-mvp.md`。

- **按时间归档个人记录**（工资条等）。属于核心库范畴（机械的归档规则），但优先级低于把材料数据库+表单代填这条主线跑通。
- **从工作周报自动生成简历要点**。属于 Agent 层范畴（需要总结和写作判断），和材料/表单这条主线关系不大，适合作为独立的后续模块。
- **证件照管理与规格校验**（存储、按用途分类、校验是否符合某国签证的尺寸/背景要求）。存储和分类部分属于核心库；校验部分可能只需要普通图像处理，不一定需要模型判断，留给下一轮架构讨论时评估。
- **小红书材料清单自动检索**（目前这一步项目主手动完成：自己搜索后把结论整理成结构化清单喂给系统）。属于 Agent 层范畴，自动化收益不确定，先手动跑几轮再决定是否值得做。
- **手机端提醒/确认联动**。例如材料快过期时提醒、在手机上确认表单字段。MVP 阶段先在桌面环境跑通闭环，移动端联动作为后续扩展。
- **GitHub 自动云同步机制的具体自动化**（例如定时自动 commit/push）。数据与代码分离的原则已经锁定（见 SPEC-mvp.md 第 3 条），但"多久同步一次、用什么机制触发"留待后续。
- **面向多用户的复用形式**（打包成别人也能装的桌面 Agent、通过 API 开放）。这会把项目性质从"个人工具"变成"要对他人敏感数据负责的产品"，涉及认证、数据隔离、隐私合规等全新的设计维度。当前策略是：把核心库的接口写得参数化、不硬编码个人场景（见 SPEC-mvp.md 第 2 条），为将来留出改造空间，但不在 MVP 阶段专门为多用户设计。
