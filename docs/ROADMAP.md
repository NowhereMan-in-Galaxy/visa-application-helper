# 路线图（2026-09-23 整理）

架构已经完整：**共享攻略**（`community/`）+ **个人办事**（材料根目录）+ **本地 Agent**（skills + MCP）+ **交互界面**（`/guides.html`、`/my.html`）。接下来不再加大模块，而是把几条主线"跑通、跑实"。

每一项写清楚：要做什么、谁来做、需要项目主提供什么、做完的标志。细节规格在对应 spec 里；新想法先进 [`BACKLOG.md`](./BACKLOG.md)。

---

## 现在（P0）：把核心闭环跑实

### 1. 跑通"外部攻略 → 流程攻略"
- **现状**：流程和工具都在（`guide-author` skill、整理指令、校验命令），但只用一份 GitHub 上已整理好的清单试过，还没用过真正杂乱的小红书/知乎帖子。
- **做法**：项目主提供 2～3 篇真实帖子（复制正文，或截图；**不自动抓取**，小红书要登录且平台规则不允许），在项目里用 `guide-author` 整理 → 校验 → 在界面里检视 → 记录为试验 #2、#3（`specs/002-guide-to-track/trials/README.md`）。最好至少一篇是**非签证**的（社保、银行补贴等），检验格式是否通用。
- **需要项目主**：挑帖子、粘贴内容；检视结果是否符合常识。
- **完成标志**：新攻略通过校验、出现在攻略库、试验记录写清楚暴露的问题和改进。

### 2. 个人计划可以自己打磨
- **现状**：个人办事里能回答问题、勾步骤、确认材料、记避坑点、设截止日期；但**不能**加自己的步骤/材料、不能隐藏不适用的步骤、不能改某一步的说明。
- **做法**：在 Track 上加一层"个人调整"（自定义步骤、自定义材料、隐藏某步、给某步加备注），只存在个人区；界面上可编辑。调整里值得分享的，可以让 Agent 整理成对共享攻略的修改建议。
- **需要项目主**：确认要支持哪几种调整（见下方"待商量"）。
- **完成标志**：spec 002 写明个人调整的数据结构；界面能加/删/隐藏；测试覆盖。

### 3. 核实并补全官网链接
- **现状**：申根攻略的链接全部来自一份 2025-07 的资料，没人核实过是否还有效；荷兰同时出现两个网址。
- **做法**：Agent 带浏览器逐个打开官网链接，确认能访问、是官方域名、页面内容对得上；更新 `as_of`；打不开或有疑问的列给项目主确认。以后每份攻略都这样做一遍再合并。
- **需要项目主**：确认有疑问的链接。
- **完成标志**：每个链接都有核实日期；失效的替换或删除。

## 接下来（P1）

### 4. 官网填表：从"流程级"到"字段级"，再到辅助填写
- **现状**：有法国、意大利两份流程级填表指南（先做什么后做什么），没有"每一栏怎么填"。
- **做法**：项目主在自己的浏览器里登录一个真实官网（建议先选法国 France-Visas），Agent 逐页记录字段结构（**只记结构，不记任何填写的值**），写成字段级指南；之后在同一份指南上做辅助填写（读个人资料逐页填，提交前由项目主确认；签名、付款、提交一律停下）。这就是 `docs/SPEC-mvp.md` 的 MVP 第 2 项。
- **需要项目主**：登录、在场确认。
- **完成标志**：一份字段级指南 + 一次辅助填写演示。

### 5. 在界面里直接问 Agent（B3）
- **现状**：安全前提（防跨站请求）和工具（MCP）都已就绪。
- **做法**：办事页加"问 Agent"，本地服务调起用户自己已安装的 Agent CLI 的非交互模式，只放行 MCP 工具，写操作要在页面上确认。先做"复制给 Agent"按钮作为过渡。
- **完成标志**：能在页面上问"我还缺什么"，得到基于真实数据的回答。

### 6. 公开之前的清理（开放共同维护的前提）
- **现状**：`materials_index/records/` 里是项目主的真实材料元数据，且在 Git 历史里。
- **做法**：个人材料索引迁到材料根目录；清理 Git 历史（改写历史，需项目主单独确认）；加贡献模板和自动校验（CI）。
- **完成标志**：`git log` 全历史里没有个人信息；新克隆的仓库里没有任何个人数据。
