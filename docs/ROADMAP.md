- **读取方式定下来了（2026-09-28）**：`xhs-reader` skill——项目主从 App 分享链接，Agent 用 Claude in Chrome 在**未登录**的浏览器里读，自动关掉登录弹窗，一次最多 6 条，遇到验证码就停。**不用项目主的账号**，避免封号。去掉 `xsec_token` 的链接和不开浏览器的匿名请求都读不到（见试验 #7）。
- **以后**：步骤没有 `note` 字段、词表缺口（每份攻略都有 5–18 条认不出的叫法）两件事，等攒够样本一起处理。
- 以下为当时的计划，保留作记录：
- **2026-09-23 更新**：输入方式优先试**小红书链接**——由 Agent 在项目主自己已登录的 Chrome 里打开单篇帖子，读正文并逐张看图（图里常有干货）；一次一两篇、由项目主发起，避免账号风控。链接行不通时再退回复制正文 / 截图。

- **做法**：项目主提供 2～3 篇真实帖子（复制正文，或截图；**不自动抓取**，小红书要登录且平台规则不允许），在项目里用 `guide-author` 整理 → 校验 → 在界面里检视 → 记录为试验 #2、#3（`specs/002-guide-to-track/trials/README.md`）。最好至少一篇是**非签证**的（社保、银行补贴等），检验格式是否通用。

- **完成标志**：新攻略通过校验、出现在攻略库、试验记录写清楚暴露的问题和改进。

### 3. 核实并补全官网链接 ✅ 已完成（2026-09-23）
- **结果**：10 个官网链接用真实浏览器逐个打开。7 个正常，已标 `verified`。修了 3 处：①荷兰：VFS 在中国已不办理，`cn.tlscontact.com` 打不开，按荷兰政府官网改成 TLScontact（`visas-nl.tlscontact.com`）；②法国 TLScontact 的 `.cn` 会跳到 `.com`，已改成跳转后的网址；③原资料 GitHub 链接的分支名写错（`main` → `master`）。
- **经验**：用 `curl` 检查时，7 个签证中心有 6 个返回 403（反机器人保护），但用浏览器打开都正常，所以不能拿 403 判定"失效"。遇到 Cloudflare 人机验证时，等它自动放行，不代点。
- **以后**：每份新攻略合并前都这样核实一遍（已写进 `guide-author` skill 和 spec"链接核实"）。
- **现状**：申根攻略的链接全部来自一份 2025-07 的资料，没人核实过是否还有效；荷兰同时出现两个网址。
- **做法**：Agent 带浏览器逐个打开官网链接，确认能访问、是官方域名、页面内容对得上；更新 `as_of`；打不开或有疑问的列给项目主确认。以后每份攻略都这样做一遍再合并。
- **需要项目主**：确认有疑问的链接。
- **完成标志**：每个链接都有核实日期；失效的替换或删除。
