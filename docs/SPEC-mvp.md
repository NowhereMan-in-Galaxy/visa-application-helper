## 2. 架构边界：核心库 vs Agent 层（已锁定原则，实现细节待定）

项目分两层，边界如下：

- **核心库（纯代码，不依赖任何模型调用）**：材料记录的存储和查询、过期状态判断（日期比较）、表单字段映射的**执行**（给定已经探索好的映射配置和材料数据，机械地把值填进对应字段）。这一层要求确定性：相同输入永远得到相同输出，且要能独立于任何 Agent 环境运行、单独测试。
- **Agent 层（需要判断和探索能力，依赖模型）**：第一次遇到新网站表单时的结构探索（识别字段、决定映射关系）、任何需要理解非结构化内容的任务（例如未来可能做的材料清单检索）。Agent 层完成一次探索后，**必须把结果写成核心库能读取执行的配置**，不能让下一次同样的操作还要重新调用模型。

> **部分替换（2026-09-24）**：上面"Agent 层完成一次探索后必须写成配置"这一条**不再适用于表单代填**（见第 1 条第 2 项的替换说明）：填表由 Agent 每次当场看页面完成，不保存字段映射。核心库对填表的职责缩小为"提供确定性的基本信息读写"。其他 Agent 层任务仍按原则执行。

> **补充（2026-09-28，通用填表引擎）**：填表拆成"确定性引擎 + Agent"两部分（specs/005-fill-engine）。引擎用共享区的同义词表 `community/form_fields.yaml` 认出常见格子，从「基本信息」取值一次填完一页；Agent 只处理引擎认不出或需要判断的格子。识别判断写在 Python（`src/form_engine/match.py`，可单测），页面里只运行扫描和填写两段小脚本，以后的浏览器插件复用同一套判断。同义词表是"格子旁边会写什么字"，不针对某个网站，不算上面取消的"字段映射配置"；**网站专用对照表**（第 2 层）和"填完一页记下结构、生成对照表草稿"的贡献流程排在下一步，届时再更新这里。

> **补充（2026-09-29，浏览器插件，spec 006）**：填表的主要方式改为浏览器插件——插件自带引擎脚本，直接问本地服务 `POST /api/ext/plan` 要计划，不经过 Agent（试验 #10：经 Agent 转发脚本每页一两分钟）。安全边界的新规则：本地服务的防跨站检查**只额外放行本项目插件**（`manifest.json` 里固定公钥 → 固定 ID `ojaapcocccendgphoehaamchlchjfmok`），而且只放行 `/api/ext/` 下的接口；其他来源的规则不变。插件对每个网站的读写权限由用户在 Chrome 弹窗里逐个同意；条款禁止自动化的网站记在 `community/site_policies.yaml`，要用户勾选"我知道风险"才填。

> **补充（2026-09-28）**：界面里的 Agent（spec 004）由本地服务调起用户自己已安装、已登录的 Agent CLI（第一版是 Claude Code 的 `claude -p`），项目不保存任何 API key。后台 Agent 不能直接写文件或跑命令：写共享区只能写草稿（放在材料根目录），由用户在页面上确认后，才由核心库的确定性代码发布进 `community/`。

任何新功能加入前，先问它属于哪一层；如果分不清，先在 Agent 层做原型，观察规律后再下沉成核心库的确定性逻辑。

## 3. 数据与代码分离（已锁定，安全相关，见 AGENTS.md 第 3 条）

- 本仓库（Git 管理）只存代码、配置、共享攻略和虚构示例。~~结构化索引（不含真实内容的元数据）也放在仓库里~~——**2026-09-24 替换**：个人材料的索引（类型、日期、状态、文件路径）同样算个人信息，放在材料根目录下的 `index/records/`、`index/applications/`，由 `config.get_materials_index_dir()` 决定，不进仓库。原因：索引放在仓库里时，即使后来被忽略，旧提交里仍有这些文件，跨这些提交合并/切换时 git 会删掉本机的真实文件（2026-09-24 发生过一次）。
- 真实材料文件存放的位置**必须可配置，不能硬编码在代码里**。项目主提出这一点是为了两个目的：一是他本人的真实材料应该能放在自己习惯的位置（不强制搬家），二是希望这个项目未来如果被别人用类似逻辑复用，"材料放哪"不该是写死在代码里的个人路径。具体做法：
  - 用一个配置文件（例如 `config.yaml` 或 `.env`，具体格式留给下一轮架构讨论）声明"材料根目录"指向哪里。
  - 这个根目录默认可以是项目文件夹内部的 `materials/`（已经在 `.gitignore` 里排除，不会被提交），也可以指向项目文件夹之外任意路径（例如项目主自己的个人材料归档空间）——两种都要支持，由配置决定，不由代码里的固定路径决定。
  - 材料索引记录中，指向真实文件的字段只存**相对于"材料根目录"的相对路径**，不存绝对路径、不复制文件内容进仓库——这样即使根目录换了位置，索引本身不用跟着改。
