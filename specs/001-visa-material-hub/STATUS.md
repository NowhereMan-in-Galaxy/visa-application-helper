## 这次会话额外做的、不在原 4 个 User Story 里的事

- **前端改成三个 tab**（个人材料 / 办事材料准备 / 工作经历和简历），固定在页面底部，样式类似手机 App 的底部导航。这是项目主直接要求的 UI 改版，不是哪条 FR 驱动的，`spec.md` 没有为此新增条目——如果以后这三个 tab 的边界需要再调整，直接改 `web/` 即可，不用先改 spec。
- **"工作经历和简历" tab 只是占位符**，没有任何存储/展示逻辑。这个 tab 的存在本身呼应的是 `docs/BACKLOG.md` 里"从工作周报自动生成简历要点"那条（依然是 backlog，没有转正）——项目主明确说了这次只搭 UI 骨架，内容范围留到下一轮决定，**不要在没有跟项目主确认范围的情况下开始往这个 tab 里加功能**。

## 已知的粗糙点 / 技术债

1. **"个人材料" tab 名不副实**：护照扫描件、证件照这两类现在展示在"个人材料" tab 下，暗示"跟哪次签证申请无关"，但数据层面 `MaterialRecord.belongs_to` 仍然是必填字段，这两类记录实际上还是按当前选中的签证申请过滤的——跟 `PersonalProfile`（真正做到了申请无关）不是一回事。如果要让这个 tab 名副其实，需要一次单独的数据模型调整（让 `belongs_to` 对这两类材料变成可选，或者引入"申请无关材料"的概念），这次没做。
2. **MaterialRecord 只能新增，不能编辑/删除**：护照扫描件/财务状态/职业材料/证件照这四类，录错了现在只能去 `materials_index/records/` 手动删 YAML 文件改，前端没有编辑入口（`travel_history` 有编辑入口，这四类没有，不对称）。
3. **财务快照的"按用途分组"没做**：`spec.md` FR-001 要求财务状态材料"按用途分组、组内按时间排列"（比如"工资流水"和"存款证明"分开看各自的时间线），现在 `financial_snapshot` 类别下所有记录是平铺列表，没有按 `sublabel`/用途做二次分组。
4. **材料根目录指向外部路径这条路径没有实测过**：`config.example.yaml` 支持把 `materials_root` 指向项目外的路径（比如 iCloud），但目前只跑通过默认的项目内 `materials/`，没有真实验证过指向外部路径的完整流程。
5. **没有集成测试/端到端测试**：`tests/unit/` 只覆盖了 `src/core/` 里的纯函数逻辑（状态计算、更新提醒），API 层和前端交互目前全靠人工在浏览器里点验证，没有自动化回归保障——改动大的地方（尤其是 `src/api/app.py`、`web/assets/app.js`）之后最好重新过一遍手工验证清单（见下）。
6. **本地服务是手动用 `nohup ... &` 起在后台的**，没有做成随系统启动的常驻服务，也没有配置热重载(`--reload`)下长期稳定运行的验证——改了 `src/` 下的 Python 代码要记得重启服务（改 `web/` 下的静态文件不用，刷新浏览器就行）。

## 手工验证清单（改动较大之后建议过一遍）

1. `uv run pytest tests/` 全过。
2. 重启服务（`pkill -f "uvicorn api.app:app"` 之后重新 `uv run uvicorn api.app:app --app-dir src --port 8000`）。
3. 浏览器打开 `http://127.0.0.1:8000`，三个 tab 都能正常切换。
4. "个人材料" tab：出行记录能新增、能编辑已有条目（尤其是国家留空的情况）；护照扫描件/证件照能新增（带文件上传和不带文件上传两种情况都试一下）。
5. "办事材料准备" tab：财务状态/职业材料能新增；状态徽章（已备齐/待补/即将过期/已过期）和"建议更新"提醒的颜色、文案符合预期。
