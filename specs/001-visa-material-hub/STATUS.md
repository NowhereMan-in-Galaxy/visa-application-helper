## 这次会话额外做的、不在原 4 个 User Story 里的事

- **前端改成三个 tab**（个人材料 / 办事材料准备 / 工作经历和简历），固定在页面底部。项目主直接要求的 UI 改版，`spec.md` 没有为此新增条目——如果以后这三个 tab 的边界需要再调整，直接改 `web/` 即可，不用先改 spec。
- **"工作经历和简历" tab 只是占位符**，没有任何存储/展示逻辑。呼应 `docs/BACKLOG.md` 里"从工作周报自动生成简历要点"那条（依然是 backlog，没有转正）——**不要在没有跟项目主确认范围的情况下开始往这个 tab 里加功能**。
- **`MaterialRecord.belongs_to` 改成可选字段**（原来必填）。证件类（护照/身份证/户口本，现在合并成一个 category）和证件照，`belongs_to` 不再挂靠某次具体申请，跨申请聚合展示成"个人材料库"——这是项目主明确要求的信息架构，已经写进 `spec.md` FR-002/FR-003（本轮改的，不是原来就有的）。**注意**：决定一条记录展示在哪个 tab 是看 `category`，不是看 `belongs_to` 是否为空——哪怕某条证件记录的 `belongs_to` 历史上有值，只要 `category` 属于"个人材料"这一组，照样会被聚合展示，这个实现细节容易被后来者搞反。
- **导入了一批真实材料**：项目主桌面「澳大利亚签证」文件夹里的真实文件（护照盖章页、身份证、户口本、银行流水、在职证明等），已经复制进 `materials/`（不进 git）、在 `materials_index/` 建了索引。这次签证已经提交，不是活跃事项，建的 `australia-business-visitor-2026` 这条 `VisaApplication` 主要是当"办事材料准备" tab 的真实测试数据用，不需要再跟踪它的 DDL。原文件夹里另外 4 份文件（身份证/户口本已经处理了，这里指邀请函、Cover Letter 等）现有类别覆盖不到或者内容还没定稿，没有搬，见对应的 git commit message。
- **"追加新页"功能**：`file_ref` 指向 PDF 的材料记录，现在可以上传一张新图片/PDF，追加进已有文件末尾（`src/core/pdf_merge.py`），不用新建记录。合并失败会自动回滚，不留半成品文件。

## 已知的粗糙点 / 技术债

1. ~~"个人材料" tab 名不副实（`belongs_to` 仍然必填）~~ **已解决**（本轮）：`belongs_to` 改成可选，证件类和证件照现在是真正的"申请无关"个人材料库。
2. **MaterialRecord 大部分字段还是不能编辑/删除**：护照/财务/职业/证件照这四类，除了"追加新页"（只更新 `obtained_date` 和文件内容）之外，其余字段（`type`、`sublabel`、`validity_days` 等）录错了现在只能去 `materials_index/records/` 手动改 YAML，前端没有通用编辑入口（`travel_history` 有编辑入口，不对称）。
3. **财务快照的"按用途分组"没做**：`spec.md` FR-001 要求财务状态材料"按用途分组、组内按时间排列"，现在 `financial_snapshot` 类别下所有记录是平铺列表，没有按 `sublabel`/用途做二次分组。
4. **材料根目录指向外部路径这条路径没有实测过**：`config.example.yaml` 支持把 `materials_root` 指向项目外的路径（比如 iCloud），这次导入真实材料时用的还是默认的项目内 `materials/`，没有验证过指向外部路径的完整流程。
5. **没有集成测试/端到端测试**：`tests/unit/` 只覆盖了 `src/core/` 里的纯函数逻辑，API 层和前端交互全靠人工在浏览器里点验证——改动大的地方之后最好重新过一遍下面的手工验证清单。
6. **本地服务是手动用 `nohup ... &` 起在后台的**，没有做成随系统启动的常驻服务——改了 `src/` 下的 Python 代码要记得重启（改 `web/` 下的静态文件不用，刷新浏览器就行）。
7. **"追加新页"只支持 PDF**：给单页图片类型的记录（比如证件照的 `.jpg`）追加/合并页面目前不支持，只能新建一条记录（见 `spec.md` Edge Cases）。
8. **财务状态、职业材料还是不能跨申请复用**（`spec.md` FR-002 里的 SHOULD 还没实现）：同一份材料如果两次不同的签证申请都要用，现在还是得录两条记录。证件类已经通过"belongs_to 可选 + 按 category 聚合"解决了同样性质的问题，财务/职业材料要不要照搬同一套解法，留给下一轮评估。

## 手工验证清单（改动较大之后建议过一遍）

1. `uv run pytest tests/` 全过。
2. 重启服务（`pkill -f "uvicorn api.app:app"` 之后重新 `uv run uvicorn api.app:app --app-dir src --port 8000`）。
3. 浏览器打开 `http://127.0.0.1:8000`，三个 tab 都能正常切换；"个人材料" tab 不用选签证申请就能看到证件类材料，"办事材料准备" tab 里的签证申请选择器能正常切换、财务/职业材料跟着变。
4. "个人材料" tab：出行记录能新增、能编辑已有条目（尤其是国家留空的情况）；证件类能新增（带文件上传和不带文件上传两种情况都试一下）；PDF 类型的记录能"追加新页"。
5. "办事材料准备" tab：财务状态/职业材料能新增；状态徽章和"建议更新"提醒的颜色、文案符合预期。
